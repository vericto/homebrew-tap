# Contributing to the Vericto Homebrew tap

Thanks for your interest in the Vericto Homebrew tap. This repository only
packages the [Vericto CLI](https://github.com/vericto/vericto-cli) for Homebrew;
its files are under the [BSD 2-Clause License](LICENSE).

## Code of Conduct

This project follows the [Contributor Covenant](CODE_OF_CONDUCT.md). Be
respectful, constructive, and technically precise.

## What belongs here

- **The tap's CI** — `.github/workflows/tests.yml` and
  `.github/test-formulae.sh`, which style-check, audit, install and test each
  formula on Linux (x86_64, arm64) and macOS (arm64, x86_64).
- **Documentation** — `README.md`.

What does not:

- **`Formula/vericto.rb`.** It is generated by cargo-dist in the CLI's release
  workflow and pushed here by its `homebrew-publish` job, which waits for
  approval of the CLI repository's `prod` environment. Do not edit it by hand:
  the next release replaces it. A fix to the formula (URLs, checksums, the
  `test do` block, install steps) belongs in
  [vericto/vericto-cli](https://github.com/vericto/vericto-cli), in
  `dist-workspace.toml` or `.github/workflows/homebrew-publish.yml`.
- **The CLI itself** (flags, output, exit codes) →
  [vericto-cli issues](https://github.com/vericto/vericto-cli/issues/new/choose).

A problem that only shows up through Homebrew (an install, checksum or upgrade
failure) can be opened here as an issue.

## Testing locally

```bash
brew tap vericto/tap "$PWD"        # tap this checkout
bash .github/test-formulae.sh      # brew style, audit --strict --online, install, test, linkage
brew uninstall vericto             # the script installs the formula; remove it afterwards
brew untap vericto/tap
```

The script trusts the tap (`brew trust --tap vericto/tap`) and waits up to 15
minutes for the release archives, because the CLI's release pushes the formula
shortly before the GitHub release is announced.

## Pull requests

- Required checks: `linux (x86_64)`, `linux (arm64)` and `gitleaks`. The
  `macos (...)` jobs run on every push and pull request too and should be
  green.
- Keep actions pinned to full commit SHAs with a version comment, as in
  vericto-cli; Dependabot keeps them current.
- Write commit messages, comments and pull request descriptions in English. The
  formula commits from the CLI release are named `vericto X.Y.Z`.
- At least one maintainer review (CODEOWNERS requests it).
- The Contributor License Agreement is signed (`CLA` check, see below).

Pull requests are merged with a merge commit; squash and rebase merges are
disabled.

## Releases

This repository has no releases or changelog of its own. Each
[vericto-cli release](https://github.com/vericto/vericto-cli/releases) (a
`vX.Y.Z` tag there) publishes the new formula to `main` here; its changes are
in the CLI's [CHANGELOG](https://github.com/vericto/vericto-cli/blob/main/CHANGELOG.md).

## Reporting security issues

Do **not** open a public issue for vulnerabilities. See [SECURITY.md](SECURITY.md)
or email [security@vericto.com](mailto:security@vericto.com).

## Contributor License Agreement

Before a pull request can be merged, every human commit author must sign the
Vericto Individual Contributor License Agreement, version 1.1
([CLA index](CLA.md), permanent text [legal/cla/1.1.md](legal/cla/1.1.md)). The
agreement lets Vericto distribute accepted contributions under the project's
public license and under separate commercial licenses while the contributor
keeps copyright.

Read the agreement and post this exact pull-request comment:

```
I have read the CLA Document and I hereby sign the CLA
```

The CLA workflow records your GitHub username and numeric account ID,
repository ID, pull-request number, comment ID, comment timestamp, CLA version
and SHA-256 document hash in `signatures/v1.1/cla.json` on the
`cla-signatures` branch. The data and retention are described in
[CLA_PRIVACY_NOTICE.md](CLA_PRIVACY_NOTICE.md). If the check does not rerun,
comment `recheck`. A commit whose email is not linked to a GitHub account
cannot be matched to a signer. Closed pull requests are locked to preserve the
signature comment.

If an employer, client or other person may own rights in your contribution,
obtain written authorization and send it to
[legal@vericto.com](mailto:legal@vericto.com) before submitting.
